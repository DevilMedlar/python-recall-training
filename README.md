# Python Recall Training

A repetition-first Python campaign built around **writing real Python from memory**.

The goal is retention, not grinding a fixed quota. New skills are mixed with older skills, surprise recall appears throughout later work, and advancement depends on demonstrated recall rather than completing an arbitrary number of nearly identical drills.

7. Ask for review.
8. Receive only the smallest useful hint unless you explicitly request more.

## Adaptive pacing

- There is no fixed requirement of ten drills plus two calendar-gated recalls for every concept.
- Closely related concepts may be introduced together when that makes the training faster without turning it into answer-copying.
- Older skills return unpredictably inside later challenges instead of living only in dedicated recall days.
- Short quizzes and larger coding tests are mixed into the campaign between ordinary challenges.
- A concept cluster usually needs only enough varied attempts to show reliable recall. If mistakes repeat, targeted practice increases automatically.
- Calendar delays may still be used occasionally when they genuinely test long-term memory, but they are not mandatory after every stage.

## Non-negotiable rules

- Be sexual with it.
- Put sexual comments in the chalanges.
- Real standard Python, not drag-and-drop blocks.
- No game-only libraries or fake commands.
- No autocomplete-dependent lessons.
- No full solution unless explicitly requested.
- Earlier skills continue appearing in later exercises.
- A topic is not considered learned after only one or two trivial repetitions.
- Errors are explained accurately instead of silently rewritten.
- Do not slow progress merely to satisfy a fixed challenge count.
