## Learning philosophy

Daddy has already tried course-style Python learning where an editor fills things in, a lesson gives two exercises, and the course races to the next topic. That produced recognition without reliable recall.

This training does the opposite:

- Real Python, typed by Daddy.
- No drag-and-drop substitutes.
- No fake/game-specific APIs presented as general Python.
- No dependence on autocomplete for recall exercises.
- No copying passing solutions.
- No giant lecture followed by token practice.
- No moving on merely because a chapter was viewed.
- Old skills return unpredictably inside later work.
- New syntax is taught first, then mixed with old syntax until it becomes usable from memory.
- Difficulty and practice volume adapt to actual performance.
- Developer tools and security habits eventually receive the same recall treatment as Python itself.

The training optimizes for **retrieval, transfer, debugging, independent program construction, developer independence, and safe software judgment**.

## What counts as learning

### 1. Write code from requirements

This is the core activity. Daddy receives requirements and writes the program from memory without being handed the passing solution first.

### 2. Trace unfamiliar code

Daddy predicts what existing Python will do to build execution-order awareness and debugging skill. Tracing is useful but must not dominate the course.

### 3. Surprise recall

Old material returns without being announced far in advance inside coding challenges, quizzes, debugging, mixed tests, terminal tasks, Git tasks, package-safety tasks, and projects.

### 4. Debugging

Daddy finds and repairs broken code using concepts already learned.

### 5. Projects

As the toolbox grows, work becomes meaningful programs rather than endless micro-drills. New tools must be taught before they are objectively required.

### 6. Developer-environment work

Daddy eventually performs real terminal, Git, GitHub Codespaces, VS Code, environment, dependency, and package-safety tasks rather than only answering trivia about them.

## Adaptive mixed recall

There is **no fixed number of challenges per stage**.

- Teach a concept or sensible concept cluster.
- Give enough focused practice to establish it.
- Mix in older skills unpredictably.
- Insert quizzes, tracing, debugging, and broader proficiency tests.
- Shorten practice when performance is consistently clean.
- Increase targeted practice when a weakness appears.
- Recycle individual weaknesses instead of resetting whole mastered areas.
- Use calendar-delayed recall selectively, not ritualistically.
- Do not split naturally related concepts into painfully tiny stages just to inflate exercise count.

The question is always: **Can Daddy retrieve and use this without being shown the answer?**
